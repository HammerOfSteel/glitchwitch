# Glitch Witch — Design Bible

The reference for how the game looks, sounds, feels, and is built. When in doubt, return
here. When this document is wrong, change it deliberately (docs commit, same ritual).

## Pillars

1. **Little Witch in the Woods cadence.** Chaptered mainline gated by craft + friendship;
   dense side stories; a daily loop of gather → brew → help → befriend; an observation
   journal that makes noticing things a mechanic. No combat — **mending instead of fighting**.
2. **Wholesome with teeth.** Cozy is the default register. Stark subjects (automation and
   livelihood, digital grief, anxiety, bereavement, shifted seasons) live in clearly
   signposted optional chains with content notes and off-ramps. Hope without erasure.
3. **Diegetic systems.** Album canon: every ritual is both spell and system call. The
   journal is a pair of magpies. Saves are snapshots. The weekly update is Patch Day,
   chalked on the pantry door. The grimoire is a runbook. UI lives in the world wherever
   possible.
4. **Toy-box look.** Low-poly palette-atlas meshes, toon ramp + outlines, diorama framing.
   The Animal Crossing / 3DS register: soft, rounded, huggable, slightly miniature.
5. **Code-first reproducibility.** Assets are generated by deterministic, seeded code or
   fetched at pinned versions. A fresh clone + two commands rebuilds everything.

## Art direction

### The toy render

- **Renderer:** GL Compatibility (portable, web-friendly, honest about its simplicity —
  the constraint *is* the aesthetic).
- **Meshes:** low-poly, chunky silhouettes, rounded where the eye rests. Triangle budgets
  are asserted in tests (see budgets below).
- **Texturing:** a single generated **palette atlas** per palette variant. UVs point at
  flat color cells — no painted textures. This gives: perfect color coherence, tiny
  downloads, and colorblind-safe alternates by swapping one texture.
- **Shading:** toon ramp (2–3 soft steps), gentle rim light, inverted-hull outlines in a
  dark warm tone (never pure black). Ambient comes from a soft gradient sky.
- **Framing:** slight vignette; depth-of-field at diorama moments; the world should feel
  like something kept on a shelf and loved.

### Palette color script

Generated by `tools/assetgen` from a single source of truth (`palette.py`):

- **Village / hearth:** warm honey, cream, terracotta, moss green, cardigan rust.
- **Forest / fen:** cool teal, loam brown, lichen grey-green, bluebell dusk.
- **The Seams / glitch:** magenta-static, signal cyan, void plum — used *sparingly*, as
  punctuation, never as wallpaper.
- Ramps per material family (wood, stone, leaf, cloth, ceramic, metal, sky) with 3–4
  steps each; cells are addressable by name in the generator API.

### The glitch vocabulary

Each anomaly type has exactly one visual verb, so players learn to *read* the world:

| Anomaly | Visual verb |
|---|---|
| Loop | time-quantized/repeating animation (bird re-flies its arc) |
| Lag | trailing ghost / delayed shadow |
| Dupe | twinned object with slight offset (two kettle whistles) |
| Seam | thin wireframe tear revealing gridlight beneath |
| Missing | magenta-checker material on a familiar thing |

Rules: glitches are **diegetic, meaningful, and rare** — they mark quest content, never
random decoration. **Reduce-glitch mode** (accessibility, photosensitivity) swaps every
verb for a gentle shimmer + icon badge; it must ship alongside each verb, not later.

## Camera & controls

- **Third person (default):** orbit follow with spring-arm collision, soft auto-framing
  toward interactables, shoulder-nudge in narrow interiors. Cozy, slow lerps, no snap.
- **First person (toggle, anytime):** for looking closely at the small world.
- **Witch Sight (overlay mode):** the diagnostic lens — reveals seams, ingredient
  glimmers, and sigil traces via a cull-mask layer + shader pass. Available in both
  camera modes, richest in first person. This is the game's "observation mode" and the
  reason first person exists narratively.
- **Shipped tuning (Phase 1):** walk 2.2 m/s · run 4.2 · accel 10 · decel 14 (stops kinder
  than starts) · turn lerp 10 · gravity 18 · pitch clamp −71.6°..+45.8° · zoom 1.6–5.0 m ·
  FOV 50° third / 70° first · camera follow lerp 12 · seam objects on **render layer 2**
  (default cull mask excludes it; Witch Sight adds it back).
- Input: keyboard+mouse and gamepad from day one; bindings defined **in code**
  (`src/core/input_bootstrap.gd`) because Phase 3 builds player rebinding on runtime
  `InputMap` anyway. Actions: move (4), run, interact, camera_toggle, witch_sight,
  journal, pause (+ more per phase as systems land).

## Audio architecture

- **Bus tree:** `Master → Music (→ 4 stem-layer sub-buses) / Ambience / SFX / UI / Voice`.
- **AudioDirector** reads `content/music/manifest.json`: stems → buses → zone/story
  states, with crossfade rules. The owner's adapted album stems drop in later with zero
  code changes; until then the manifest points at generated ambience beds.
- **SFX:** CC0 packs (Kenney et al., logged in LICENSES.md) + synthesized foley (kettle
  whistles, jar clinks, chalk scratch, magpie clacks).
- **Voices:** animalese-style pitched gibberish, synthesized per NPC voice profile
  (base pitch, timbre, pace). Captions/subtitles always available.

## Performance budgets (asserted, not vibes)

- Props: ≤ 600 tris (hero props ≤ 1,500). Characters: ≤ 4,000 tris.
- Zones: ≤ 150k tris in view, ≤ 120 draw calls (MultiMesh for scatter, one material
  per palette variant).
- Targets: 60 fps desktop, 30 fps web at 1080p. Budgets tested per asset in
  `tests/python`, per zone in gdUnit scene tests.

## UI style

- Diegetic first: The Runbook (grimoire = help/menus), jar labels (inventory), the
  pantry-door changelog (patch notes), the magpie log (journal).
- Type: rounded, generous, readable at 3DS-ish sizes; text scale setting from Phase 3.
- Tone of system text: kind, a little playful, never sarcastic at the player's expense.

## Asset pipeline (decision record)

- `tools/assetgen` is **pure Python (stdlib only)** for props, nature, and building
  assets: mesh kit → GLB writer, palette → PNG writer. Deterministic under fixed
  seeds; byte-hash tested. Rationale: zero heavy dependencies in CI/sandbox, total
  reproducibility, fast iteration. **Unchanged by the pivot below** — this is still
  where every prop/nature/building placeholder in the game comes from today.
- **Character & environment art generation is sourced externally for now (pivot,
  see `docs/superpowers/specs/2026-08-09-external-asset-pivot-design.md`):** rather
  than continuing to build and tune an in-house Blender procedural character
  pipeline (or an equivalent in-house nature/building pipeline), the project owner
  will generate final character art via Meshy AI (or a similar tool) and source
  environment/building art from free/CC0 low-poly modular packs, outside this
  repo's build. This keeps the small-in-house-pipeline burden off a project the
  owner is running alongside several others.
  - The **Blender-backed character-pipeline-v2** work
    (`tools/assetgen/blender/`, `tools/assetgen/blender/base_humanoid.blend`) is
    **paused, not deleted** — Tasks 1–11 are committed and test-covered; Task 12's
    orchestrator has a known unresolved tri-budget failure. It may resume later if
    in-house procedural generation becomes worthwhile again; until then no further
    work lands on it.
  - **Placeholder policy while external art is sourced:** the v1 procedural
    character stack (`tools/assetgen/character_gen.py` et al., producing
    `assets/generated/wren.glb` / `villager.glb`) and the v1 procedural
    props/nature stack (`tools/assetgen/props.py`, producing
    `assets/generated/{pine,fence,crate,jar,mug,ground_tile}.glb`, used in
    `src/sandbox/glade.tscn`) both remain the working placeholders — nothing
    about them changes or gets removed.
  - **Wren specifically** additionally has a rigged/animated placeholder body,
    `assets/thirdparty/wren_placeholder/wren_placeholder.glb`, built by
    `tools/assetgen/placeholders/fetch_wren_placeholder.py` from a Seren
    (Meshy AI) rigged+animated export the owner already produced for a separate
    project. `WrenAvatar` (`src/player/avatar.gd`) loads this in place of the
    procedural `wren.glb` when present, with `USE_PLACEHOLDER := true`, and falls
    back to the procedural body if it hasn't been built locally. This is a
    stand-in only — it ships its own baked material (palette dressing is skipped
    for it) and has no wave/stir gesture clips (gestures no-op gracefully).
- **CC0 skinned bases (KayKit / Quaternius)** remain documented as a fallback for
  the base-mesh-only approach *if and when* in-house Blender character work
  resumes — see
  `docs/superpowers/specs/2026-08-08-character-pipeline-v2-blender-design.md`.
- `assets/generated/` and `assets/thirdparty/` remain build outputs, ignored by
  git, rebuilt by `make assets` / bootstrap / the placeholder fetch script above —
  this is unchanged. The one exception is the committed `base_humanoid.blend`
  *source* asset itself, which lives under `tools/assetgen/blender/` (alongside
  the code that consumes it, paused as noted above), not under
  `assets/generated/`.
